# 灯具跟踪 HTTP / Three.js 模拟器设计

## 目标

在本机模拟 ESP8266 灯具的局域网 HTTP 控制接口，用可视化场景核验由摄像头机位转发的跟踪角度。页面须清楚呈现 `pan` 与 `tilt` 的正负方向：`pan < 0` 向左，`tilt < 0` 朝灯具前方的墙面。

## 范围与协议

模拟器提供与固件 `handleLampControl()` 相同的入口：`POST /lamp/control`。它接受 JSON 请求体，并接受 CORS 预检 `OPTIONS` 请求。

支持字段：

- `pan`：可选，绝对水平目标角度；按固件边界截断至 -45 到 45 度。
- `tilt`：可选，绝对俯仰目标角度；按固件边界截断至 -90 到 90 度。
- `brightness`：可选，0 到 100；用于预览光照强度。
- `temp`：可选，单位 Kelvin；按固件范围 2700 到 6500 截断，用于预览光色。

任一未传入的字段保持上一次有效值。HTTP 成功响应为 `{"result":"OK"}`；缺少请求体或 JSON 无法解析时返回 400。

模拟器显示的是 HTTP 指令的目标值，而不是固件的 `panDeg` / `tiltDeg` 状态变量：现有 `/lamp/control` 实现会直接调用电机下发函数，未回写这两个状态变量。Nano 的 tilt 下发比例 30/48 只影响串口命令，不改变本设计中可视化的机械目标姿态。

## 架构

`tracking-simulator/server.mjs` 是零依赖 Node HTTP 服务：它托管 `index.html`，处理 `/lamp/control`，维护最后有效状态，并通过 Server-Sent Events 的 `/events` 将每次状态更新推送给所有已打开的页面。

`tracking-simulator/index.html` 使用 CDN 加载 Three.js。它订阅 `/events`，并提供一个手动 JSON 发送框，方便不接入摄像头设备时复现请求。由于浏览器本身不能作为 HTTP 服务端，HTTP 接收能力必须由 `server.mjs` 承担。

## 可视化与坐标

场景中墙面放在灯具前方，灯具在墙前固定。零位朝向为前方墙面；水平角负值绕竖直轴向左偏转；俯仰角负值向下/前方倾斜，因此光束更贴近并投向墙。灯具模型、光锥、中心射线和墙面落点共同显示当前方向。

页面额外显示原始 JSON、接收时间、原始输入值、截断后的有效状态与请求日志。亮度控制光锥强度，色温控制光色。只有实际下发到模拟接口的值会改变画面。

## 错误处理与验证

服务端对非 POST / OPTIONS 的控制请求返回 405；空请求体与非法 JSON 返回 400。页面在 SSE 断开时显示连接状态，并可通过手动发送区继续复现错误。

实现后使用下列请求验证：

```json
{"tracking":true,"pan":-11.2,"tilt":-18.1,"brightness":80,"temp":4000}
```

预期结果是服务端返回 200 和 `{"result":"OK"}`，页面显示左偏、向墙倾斜的光束，状态值为 `pan=-11.2`、`tilt=-18.1`、`brightness=80`、`temp=4000`。
